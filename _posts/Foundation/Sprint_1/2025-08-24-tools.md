# The Student's Toolkit: Setting Up for Success
Welcome to the tools section of my blog! In this post, I’ll walk through my development setup and share how I’ve refined my workflow over time. Whether you’re just starting out or already experienced, having a reliable set of tools makes all the difference.

## Getting Started: My Core Setup
My setup began with Visual Studio Code (VSCode), a powerful yet lightweight editor that balances simplicity and flexibility. What makes VSCode truly effective is its extension ecosystem. I installed extensions tailored to my workflow—ranging from syntax highlighting to integrated running and debugging tools.

To keep projects organized and secure, I connected VSCode with GitHub for version control. This setup lets me track every change, collaborate efficiently, and maintain an accessible online backup of my work.

<img src="{{ site.baseurl }}/images/make.jpg" alt="make">
Working with Git and GitHub opened my eyes to the efficiency of version control. Git operates locally to manage a project’s history, while GitHub hosts repositories online. Together, they form a smooth workflow for building and maintaining projects:

Clone a repository from GitHub to create a local copy.

Make updates and commit them to record changes.

Push the commits back to GitHub to update the online version.

Having this rhythm ensures that my progress is consistent, traceable, and always backed up.

<img src="{{ site.baseurl }}/images/Git.jpg" alt="Git">

## Automating with Makefiles
After getting comfortable with VSCode and Git, I explored Makefiles—simple but powerful tools that automate repetitive tasks. A Makefile uses predefined commands to build and run your project. In my case, I used it to launch a local server and generate my website efficiently.

Running a Makefile requires nothing more than typing make into the terminal. For example, make serve instantly started a local server, saving time compared to manually running several commands. This small improvement taught me the real value of automation in development workflows.

## Learning Through Every Adjustment
This week’s biggest insight came from a minor yet instructive challenge: troubleshooting a problem with forking a repository. After some digging, I realized I wasn’t running my environment with administrative privileges. A quick fix—but one that reinforced the importance of understanding the details behind my tools.

That experience reminded me that improving your toolkit isn’t always about adding new software. Sometimes, it’s about mastering what you already have. Simple commands like sudo or understanding the difference between a local and deployed server can completely change how efficiently you work.

A localhost server, for instance, runs on your personal machine and is only visible there. A deployed server, on the other hand, runs online and can be accessed globally. Recognizing the distinction gave me a clearer picture of how development environments connect to the real world.

Continuous improvement—through learning, experimenting, and refining—has made my workflow stronger and more adaptable. Every challenge, big or small, becomes a step toward building a smoother and more reliable development process.
