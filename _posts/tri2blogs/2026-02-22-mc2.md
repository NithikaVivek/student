## Q5: SomeClass Object - Write Code

**My Answer:** B  
**Correct Answer:** A

### Question
```java
public class SomeClass {
    private int myA;

    // Constructor(s) not shown

    public int getA() {
        return myA;
    }
}
```
Assume `SomeClass` object `obj` has been properly declared and instantiated in a class other than `SomeClass`. Which statement will compile without error?

### Why I Was Wrong
I selected: `int x = obj.myA;`

`myA` is a **private** instance variable. Private variables can only be accessed from within the same class (`SomeClass`). Any attempt to access `myA` directly from another class causes a **compile error**.

### The Correct Answer
**A: `int x = obj.getA();`**

`getA()` is declared **public**, so it can be called from any class. It returns the private variable `myA` through a controlled public interface — this is the correct use of encapsulation.

Why the other options fail:
- **B:** `obj.myA` — direct access to a private field from outside the class → compile error
- **C:** `SomeClass.getA()` — `getA()` is an instance method, not static; must be called on an object
- **D:** `getA(obj)` — incorrect syntax; Java instance methods use dot notation (`obj.getA()`)

### Key Takeaway
**Private fields must be accessed through public getter methods when called from outside the class.**
- `private` = only accessible within the declaring class
- `public` = accessible from anywhere
- Never try to access `obj.privateField` from an external class — always use `obj.getField()`

## Q11: Nested If Statements - Describe Behavior

**My Answer:** B  
**Correct Answer:** C

### Question
```java
if (num > 0) {
    if (num % 2 == 0) {
        System.out.println("X");
    } else {
        System.out.println("Y");
    }
}
```

### Why I Was Wrong
I selected: "When `num` is a positive even integer, 'X' is printed; otherwise, 'Y' is printed."

The word "otherwise" is the trap. I didn't account for what happens when `num` is **not positive**. If `num <= 0`, the outer `if` is false and the entire block is **skipped** — nothing is printed at all. "Otherwise" implies Y is always printed when X isn't, but that's wrong.

### The Correct Answer
**C: When `num` is a positive even integer, "X" is printed; when `num` is a positive odd integer, "Y" is printed; otherwise, nothing is printed.**

Tracing all cases:
- `num = 4` (positive, even): outer if true → inner if true → prints **"X"** ✓
- `num = 3` (positive, odd): outer if true → inner if false → else → prints **"Y"** ✓
- `num = -5` (negative): outer if **false** → nothing printed ✓
- `num = 0`: outer if **false** → nothing printed ✓

### Key Takeaway
**Nested if statements have limited scope.** The inner `if/else` only runs when the outer `if` condition is true. Always ask: "What happens when the outer condition is false?" If the outer block has no `else`, nothing happens for that case.

## Q15: Loop to Print 987654321

**My Answer:** B  
**Correct Answer:** C

### Question
Which code segment produces the output `"987654321"`?

### Why My Answer Was Wrong
**My answer (B):**
```java
int num = 10;
while (num > 1) {
    System.out.print(num);
    num--;
}
```
This prints **then** decrements. Trace:
- num=10: prints 10, then num=9
- num=9: prints 9, then num=8
- ...continues down to 2
- Output: `"10987654321"` — starts at 10, not 9!

### The Correct Answer
**C:**
```java
int num = 10;
while (num > 1) {
    num--;
    System.out.print(num);
}
```
This **decrements first**, then prints. Trace:
- num=10: num becomes 9, prints 9
- num=9: num becomes 8, prints 8
- ...
- num=2: num becomes 1, prints 1
- num=1: 1 > 1 is false → stop
- Output: `"987654321"` ✓

### Why Not Option A?
Option A uses `while (num > 0)` with print-then-decrement, printing `"10987654321"` (wrong) followed by 0 inclusion issues.

### Why Not Option D?
Option D uses `while (num >= 1)` with decrement-then-print, which would print `"9876543210"` (includes 0).

### Key Takeaway
**Order of operations inside a loop body matters!** Decrement-before-print vs. print-before-decrement produces different output. When you need to print a derived value (like num-1), consider whether it's cleaner to update the variable first.

## Q (Point/PointChecker): Class Definitions Compile Error

**My Answer:** B  
**Correct Answer:** D

### Question
```java
public class Point {
    private double num1;
    private double num2;

    public Point(int n1, int n2) {
        num1 = n1;
        num2 = n2;
    }
}

public class PointChecker {
    public static boolean checkPoint(Point p) {
        return p.num1 > 0.0 && p.num2 > 0.0;
    }
}
```

### Why I Was Wrong
I selected: "In the Point constructor, `int` values cannot be assigned to `double` variables."

This is actually **not an error** in Java. Assigning an `int` to a `double` is an **implicit widening conversion** — Java automatically promotes the int to a double. This compiles fine. The note at the bottom of the question confirms: "When int values are assigned to double variables, they are automatically widened to double values."

### The Correct Answer
**D: In the `checkPoint` method, the instance variables `num1` and `num2` cannot be accessed from a class other than `Point`.**

`num1` and `num2` are declared **private** in `Point`. The `PointChecker.checkPoint()` method tries to access `p.num1` and `p.num2` directly from a **different class** — this causes a compile error.

### The Fix
Either make `num1` and `num2` public (bad practice), or add public getter methods to `Point`:
```java
public double getNum1() { return num1; }
public double getNum2() { return num2; }
```
Then use: `return p.getNum1() > 0.0 && p.getNum2() > 0.0;`

### Key Takeaway
**Java widening conversions are automatic** — `int` → `double`, `int` → `long`, `float` → `double` all work without casting. The real error is always the **private access violation**: private fields are inaccessible from any external class, regardless of whether you have an object reference.

## Q18: While Loop That Prints Nothing

**My Answer:** C  
**Correct Answer:** B

### Question
```java
int x = 1;
while (x < 10) {
    if (x % 2 == 0) {
        System.out.print(x + " ");
    }
    /* missing code */
}
```
Which replacement for `/* missing code */` causes the segment to print **nothing**?

### Why I Was Wrong
I selected: `x += 3;`

With `x += 3`, starting at x=1:
- x=1: 1%2≠0, no print, x becomes 4
- x=4: 4%2==0, **prints "4"** ← not nothing!
- x=7: 7%2≠0, no print, x becomes 10
- x=10: 10 < 10 is false → stop
- Output: `"4"` — not empty!

### The Correct Answer
**B: `x += 2;`**

With `x += 2`, starting at x=1 (odd), incrementing by 2:
- x=1: 1%2≠0, no print, x becomes 3
- x=3: 3%2≠0, no print, x becomes 5
- x=5: 5%2≠0, no print, x becomes 7
- x=7: 7%2≠0, no print, x becomes 9
- x=9: 9%2≠0, no print, x becomes 11
- x=11: 11 < 10 is false → stop
- Output: **nothing** ✓

Since x starts at 1 (odd) and increases by 2 each time, it only ever visits odd numbers — and the print condition requires an even number. The two conditions never overlap!

### Key Takeaway
**Think about the entire sequence of values** a variable will take, not just the first iteration. With `x += 2` starting from an odd number, x is always odd, so `x % 2 == 0` is never true. This is a parity (odd/even) argument — understanding number patterns is often key to loop analysis.

## Q20: Numbers Printed in Nested Loops

**My Answer:** A  
**Correct Answer:** C

### Question
```java
for (int outer = 1; outer <= 4; outer++) {
    for (int inner = outer; inner <= 4; inner++) {
        System.out.print(inner + " ");
    }
    System.out.println();
}
```

### Why I Was Wrong
I selected option A:
```
1 1 1 1
2 2 2
3 3
4
```
This would be the output if the code printed `outer` in the inner loop instead of `inner`. I was mentally substituting the wrong variable — a classic confusion when two loop variables exist.

### The Correct Answer
**C:**
```
1 2 3 4
2 3 4
3 4
4
```

Tracing the actual code (inner starts at `outer`, prints `inner`):
- outer=1: inner goes 1→4, prints `1 2 3 4`
- outer=2: inner goes 2→4, prints `2 3 4`
- outer=3: inner goes 3→4, prints `3 4`
- outer=4: inner goes 4→4, prints `4`

The inner loop starts where `outer` is, but it prints the value of `inner` — which **increases** each iteration.

### Key Takeaway
**In nested loops, carefully track WHICH variable is being printed vs. which is controlling the loop bounds.** Here, `outer` sets where the inner loop *starts*, and `inner` is the value actually *printed*. These are two different things. Always re-read the `System.out.print()` statement to confirm which variable is output.

## Q26: indexOf x Within String

**My Answer:** B  
**Correct Answer:** C

### Question
```java
String one = "xyz";
String two = one.substring(2) + one.substring(1) + one.substring(0);
int pos = two.indexOf("x");
```

### Why I Was Wrong
I selected: `2`

I thought `one.substring(2)` returns the empty string (a misconception), which would make `two = "yzxyz"`, and `"x"` is at index 2. But `substring(2)` does NOT return empty — it returns the character(s) starting at index 2.

### The Correct Answer
**C: 3**

Step-by-step string building:
- `one = "xyz"` (indices: x=0, y=1, z=2)
- `one.substring(2)` = `"z"` (from index 2 to end)
- `one.substring(1)` = `"yz"` (from index 1 to end)
- `one.substring(0)` = `"xyz"` (from index 0 to end = whole string)
- `two = "z" + "yz" + "xyz"` = `"zyzxyz"`

Now find `"x"` in `"zyzxyz"`:
- z(0), y(1), z(2), **x(3)**, y(4), z(5)
- `indexOf("x")` = **3** ✓

### Key Takeaway
**`String.substring(n)` returns from index n to the END of the string — it never returns empty unless n equals the string's length.** Build the string piece by piece, writing down each part explicitly. Then find the character by writing out all indices.

## Q32: Item Class - Explain Error

**My Answer:** C  
**Correct Answer:** D

### Question
```java
public class Item {
    private double price;

    public Item(double price) {
        price = price;  // BUG HERE
    }

    public double getPrice() {
        return price;
    }
}

// In another class:
Item pen = new Item(2.0);
System.out.println(pen.getPrice());  // Intended to print 2.0
```

### Why I Was Wrong
I selected: "The instance variable `price` is not assigned a value in the `Item` constructor because the constructor does not return a value."

Constructors **never** return values — that's by design, not a bug. Saying a constructor doesn't work "because it doesn't return a value" is incorrect reasoning. This is a red herring answer.

### The Correct Answer
**D: The instance variable `price` is not assigned a value in the `Item` constructor because the constructor assigns a value to the parameter instead of the instance variable.**

The bug is `price = price`. Both sides refer to the **local parameter** `price`, not the instance variable. The parameter shadows the instance variable, so the assignment just sets the parameter to itself (a no-op for the field). The instance variable `price` remains `0.0`.

### The Fix
Use the `this` keyword to distinguish the instance variable from the parameter:
```java
public Item(double price) {
    this.price = price;  // this.price = instance variable, price = parameter
}
```

### Key Takeaway
**Always use `this.fieldName = parameterName` in constructors when the parameter has the same name as the instance variable.** Without `this`, Java assumes both sides refer to the parameter, and the instance variable never gets set. This is one of the most common bugs in Java OOP!

## Q (mode method): Array Mode Algorithm - Missing Conditions

**My Answer:** C  
**Correct Answer:** A

### Question
```java
public static int mode(int[] arr) {
    int modeCount = 1;
    int mode = arr[0];

    for (int j = 0; j < arr.length; j++) {
        int valCount = 0;
        for (int k = 0; k < arr.length; k++) {
            if ( /* missing condition 1 */ ) {
                valCount++;
            }
        }
        if ( /* missing condition 2 */ ) {
            modeCount = valCount;
            mode = arr[j];
        }
    }
    return mode;
}
```

### Why I Was Wrong
I selected: `arr[j] != arr[k]` for condition 1, and `valCount > modeCount` for condition 2.

If condition 1 is `arr[j] != arr[k]`, the inner loop counts how many elements are **different from** `arr[j]` — the opposite of what we want! We need to count occurrences of `arr[j]`, not count elements that don't match it.

### The Correct Answer
**A: Condition 1 = `arr[j] == arr[k]`, Condition 2 = `valCount > modeCount`**

- **Condition 1:** `arr[j] == arr[k]` — counts how many times `arr[j]` appears in the array (correct: increment `valCount` whenever we find a matching element)
- **Condition 2:** `valCount > modeCount` — updates the mode only when we find a value with a higher count than the current best (correct: strictly greater than means we keep the first mode found in case of ties)

### Tracing with example `{6, 5, 1, 5, 2, 6, 5}`:
- j=0, arr[j]=6: counts 6s → valCount=2; 2 > 1 → mode=6, modeCount=2
- j=1, arr[j]=5: counts 5s → valCount=3; 3 > 2 → mode=5, modeCount=3
- ...remaining values won't beat 3
- Returns 5 ✓

### Key Takeaway
**When writing a frequency-counting algorithm, the inner condition must check for EQUALITY** (`==`) to count occurrences of a target value. Using `!=` counts everything else — a subtle but critical difference. Also, `valCount > modeCount` (strictly greater) ensures we return the first mode found when multiple values tie for most frequent.

## Q41: Execution Counts in Sort Method

**My Answer:** C  
**Correct Answer:** A

### Question
```java
public static void sort(int[] data) {
    for (int j = 0; j < data.length - 1; j++) {
        int m = j;
        for (int k = j + 1; k < data.length; k++) {
            if (data[k] < data[m])    /* Compare values */
                m = k;
        }
        int temp = data[m];           /* Assign to temp */
        data[m] = data[j];
        data[j] = temp;
    }
}
```
Called with `{1, 2, 3, 4, 5, 6}` (6 elements). How many times do "Compare values" and "Assign to temp" execute?

### Why I Was Wrong
I selected: 21 comparisons, 5 assignments.

I overcounted comparisons. An extra iteration doesn't exist — the outer loop runs `data.length - 1` = 5 times, not 6.

### The Correct Answer
**A: 15 comparisons, 5 assignments**

**Counting "Compare values" (inner loop):**
- j=0: k goes from 1 to 5 → **5 comparisons**
- j=1: k goes from 2 to 5 → **4 comparisons**
- j=2: k goes from 3 to 5 → **3 comparisons**
- j=3: k goes from 4 to 5 → **2 comparisons**
- j=4: k goes from 5 to 5 → **1 comparison**
- Total: 5+4+3+2+1 = **15 comparisons** ✓

**Counting "Assign to temp" (outer loop body):**
- The `int temp = data[m]` line is inside the outer loop but outside the inner loop
- Outer loop runs j=0,1,2,3,4 → **5 times** ✓

Note: 21 would be the comparison count if the outer loop ran 6 times (0 to length-1 inclusive), but `j < data.length - 1` means j only goes 0 through 4.

### Key Takeaway
**For selection sort with n elements, comparisons = n(n-1)/2.** With n=6: 6×5/2 = 15. The outer loop runs n-1 times (not n), and each "assign to temp" happens once per outer iteration. When counting nested loop executions, trace the exact bounds of each loop level — off-by-one errors in the loop condition directly affect your count.

## Overall Improvement Strategy

### 1. For Access Modifier Questions
Always identify the class where the code is written vs. the class that owns the field/method. If different classes, the member must be `public`. If `private`, it's a compile error. Don't be distracted by other issues in the code.

### 2. For Loop Tracing
Write a table: one column for each variable, one row per iteration. Include the check of the condition at the top of each iteration. Never try to trace loops entirely in your head.

### 3. For Constructor Bugs
When you see `fieldName = fieldName` inside a constructor, that's a shadowing bug. The fix is always `this.fieldName = parameterName`. Look for this pattern whenever getters return 0 or null unexpectedly.

### 4. For String Operations
Write the string with indices above or below each character. Then apply each method step-by-step, writing the result. `indexOf` returns the index of the first match, or -1 if not found.

### 5. For Counting Loop Executions
Use the formula for triangular numbers: an inner loop that counts k from j+1 to n-1 across all values of j gives n(n-1)/2 total iterations. For the outer loop, count exactly how many times j iterates based on the condition (< vs <=).
