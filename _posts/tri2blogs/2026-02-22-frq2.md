## Question 1a — `RobotMover` Constructor

### Problem Overview
Write the constructor for the `RobotMover` class. It takes an integer `numMoves` and builds a `moveSequence` string by randomly selecting `numMoves` moves (each from "up", "down", "left", "right"), with each move followed by an underscore.

### Key Concepts Tested
- String concatenation in a loop
- `Math.random()` for random selection
- Array indexing or if/else chains for discrete random choices
- Constructor syntax

### Answer
```java
public RobotMover(int numMoves)
{
    moveSequence = "";
    String[] moves = {"up", "down", "left", "right"};
    for (int i = 0; i < numMoves; i++)
    {
        int index = (int)(Math.random() * 4);
        moveSequence += moves[index] + "_";
    }
}
```

### Key Takeaways
- `Math.random()` returns a `double` in [0.0, 1.0), so multiplying by 4 and casting to `int` gives 0–3.
- Each move must be followed by `"_"` — don't forget it.
- The result looks like `"up_right_left_down_"` — trailing underscore is intentional per the spec.

## Question 1b — `countOccurrences` Method

### Problem Overview
Write `countOccurrences(String str)`, which counts how many times `str` appears in `moveSequence`. The sequence is structured as moves each followed by `_`, so substrings may span move boundaries (e.g., `"right_d"` or `"up_up"`).

### Key Concepts Tested
- String traversal with `indexOf` or substring scanning
- Counting non-overlapping (or overlapping) substring occurrences
- Loop design with index tracking

### Answer
```java
public int countOccurrences(String str)
{
    int count = 0;
    int index = 0;
    while (index <= moveSequence.length() - str.length())
    {
        if (moveSequence.substring(index, index + str.length()).equals(str))
        {
            count++;
            index++;
        }
        else
        {
            index++;
        }
    }
    return count;
}
```

> Alternatively using `indexOf`:
```java
public int countOccurrences(String str)
{
    int count = 0;
    int index = moveSequence.indexOf(str);
    while (index != -1)
    {
        count++;
        index = moveSequence.indexOf(str, index + 1);
    }
    return count;
}
```

### Key Takeaways
- The examples show `"right_d"` returning 2 and `"up_up"` returning 2 — these cross move boundaries, so you must search the **whole string**, not split by `_`.
- Using `indexOf(str, fromIndex)` is the cleanest approach.
- Increment by 1 (not `str.length()`) to catch overlapping occurrences like `"up_up"`.

## Question 2 — `LapTracker` Class

### Problem Overview
Write a complete `LapTracker` class. It takes a constructor `int` parameter indicating how often the lap count resets. `addLaps(int laps)` adds laps to a running total and resets back to 0 after every `n` calls, returning the current cumulative lap count.

### Key Concepts Tested
- Writing a complete class (instance variables, constructor, method)
- Tracking call counts to trigger periodic resets
- Accumulator pattern

### Answer
```java
public class LapTracker
{
    private int resetAfter;
    private int callCount;
    private int lapCount;

    public LapTracker(int n)
    {
        resetAfter = n;
        callCount = 0;
        lapCount = 0;
    }

    public int addLaps(int laps)
    {
        lapCount += laps;
        callCount++;
        if (callCount == resetAfter)
        {
            callCount = 0;
            lapCount = 0;
        }
        return lapCount;
    }
}
```

### Key Takeaways
- The reset happens **after** adding laps and **after** returning — actually, per the table the return value on the reset call is the **pre-reset** total (30 is returned, then reset). So: add laps → increment call count → if count == resetAfter, save result, reset, return saved result. **Or** simply return before resetting:
```java
public int addLaps(int laps)
{
    lapCount += laps;
    callCount++;
    int result = lapCount;
    if (callCount == resetAfter)
    {
        callCount = 0;
        lapCount = 0;
    }
    return result;
}
```
- Three instance variables are needed: the reset threshold, the call counter, and the running lap total.
- The lap count resets to 0 (not the added laps) — the next call starts fresh from 0.

## Question 3 — `playerWithClosestScore` Method

### Problem Overview
In the `PlayerAnalysis` class, write `playerWithClosestScore(int targetScore)`. It searches through `playerList` (an `ArrayList<Player>`) and returns the `getID()` of the player whose `getScore()` is closest to `targetScore`. If there's a tie, any valid ID can be returned.

### Key Concepts Tested
- ArrayList traversal
- Object method calls (`getID()`, `getScore()`)
- Tracking a minimum/best-so-far value
- `Math.abs()` for absolute difference

### Answer
```java
public String playerWithClosestScore(int targetScore)
{
    String closestID = playerList.get(0).getID();
    int minDiff = Math.abs(playerList.get(0).getScore() - targetScore);

    for (int i = 1; i < playerList.size(); i++)
    {
        int diff = Math.abs(playerList.get(i).getScore() - targetScore);
        if (diff < minDiff)
        {
            minDiff = diff;
            closestID = playerList.get(i).getID();
        }
    }
    return closestID;
}
```

### Key Takeaways
- Initialize with the first element, then loop from index 1 — classic "best so far" pattern.
- `Math.abs()` is essential — scores could be above or below the target.
- Return the **ID** (a String), not the score or the Player object.
- The list is guaranteed non-null and non-empty per preconditions, so no null checks needed.

## Question 4 — `countOrderedRows` Method

### Problem Overview
In the `WordGrid` class, write `countOrderedRows()`. It counts how many rows in the 2D array `grid` are ordered from shortest string to longest — meaning each element (after the first) has a length **greater than or equal to** the previous element's length.

### Key Concepts Tested
- 2D array traversal (row by row)
- String `.length()` comparison
- Boolean flag pattern for row validation
- Nested loops

### Answer
```java
public int countOrderedRows()
{
    int count = 0;
    for (int row = 0; row < grid.length; row++)
    {
        boolean ordered = true;
        for (int col = 1; col < grid[row].length; col++)
        {
            if (grid[row][col].length() < grid[row][col - 1].length())
            {
                ordered = false;
            }
        }
        if (ordered)
        {
            count++;
        }
    }
    return count;
}
```

### Key Takeaways
- The condition is `>=` (non-decreasing length), so equal lengths are **allowed** — use `<` to detect violations.
- Start the inner loop at `col = 1` so you can compare to `col - 1`.
- A single-element row is trivially ordered (inner loop never runs, `ordered` stays `true`) — this is correct behavior.
- Use a boolean flag per row; break/early exit is optional but can improve efficiency.
- From the example: rows 0 (`cat/crane/people/hamster` → 3,5,6,7 ✓), 2 (`blue/audio/adieu/snazzy` → 4,5,5,6 ✓), and 4 (`about/media/stone/canoe` → 5,5,5,5 ✓) are ordered → returns 3.
